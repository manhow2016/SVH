# V0.3-2 Storyboard / Timeline / DirectorAction 的 API 与事件面 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 V0.3-1 已交付的分镜 / 时间线 / 导演动作三组实体铺到 HTTP 与事件两层：16 条路由、3 个事件类型、SSE 信封 `projectId`，并先修掉 10 项开工前置。

**Architecture:** 路由层只做「参数解析 → 调仓储 → 发事件 → 返回读模型」，一律复用 `apps/api/src/core/validate.ts` 与全局错误处理器；归属字段（`contentId` / `trackId` / `projectId`）由路径提供，请求面与仓储面两套 schema 在 domain 里同源派生（`.refine()` 之后是 `ZodEffects`，没有 `omit` 可用）；事件投递目标由服务端解析（动作读行内存的 `sessionId`，镜头与片段用 query 参数）。

**Tech Stack:** TypeScript 5.9（纯 ESM、`module: NodeNext`）、Fastify 5、Zod 3.25、Prisma 6.19、PostgreSQL、Redis Streams、Vitest 2.1（`apps/api` 用真库真 Redis）。

**Spec:** `docs/superpowers/specs/2026-09-15-v0.3-2-storyboard-timeline-director-api-design.md`（本计划逐条对应它的 §2-§10；冲突时以 spec 为准，并回来改本文件）

```ts
    expect(HTTP_STATUS_BY_CODE.TIMELINE_CLIP_NOT_FOUND).toBe(404);
    expect(HTTP_STATUS_BY_CODE.TIMELINE_TRACK_NOT_FOUND).toBe(404);
    expect(HTTP_STATUS_BY_CODE.DIRECTOR_ACTION_NOT_FOUND).toBe(404);
    expect(HTTP_STATUS_BY_CODE.DIRECTOR_ACTION_STATE_CONFLICT).toBe(409);

  it('域内错误类带上下文与用户文案，且不泄漏技术术语', () => {
```

- [ ] **Step 4: 写三个错误类**

放在 `ContentError`（:427）之后，形状照 `AssetError`（:404）：

```ts
/**
 * 分镜相关错误。
 *
 * 只有一个码，故 code 不作为参数 —— 与 `ContentError` 同形。
 * 之所以不复用 `NotFoundError`：那个把 code 写死成 `NOT_FOUND`，
 * 而 §44 的客户端要按码分支（镜头没了要刷新分镜列表，轨道错了是调用方 bug）。
 */
export class ShotError extends SvhError {
  constructor(message: string, options: SvhErrorOptions = {}) {
    super('SHOT_NOT_FOUND', message, options);
  }
}

/**
 * 时间线相关错误：片段与轨道共用一个类，但**各用自己的码**。
 *
 * 类只负责「这条链路上的错误属于时间线」，具体码由调用方给，
 * 这样 `Extract<...>` 能在编译期挡住拼错的码。
 */
export class TimelineError extends SvhError {
  constructor(
    code: Extract<ErrorCode, 'TIMELINE_CLIP_NOT_FOUND' | 'TIMELINE_TRACK_NOT_FOUND'>,
    message: string,
    options: SvhErrorOptions = {},
  ) {
    super(code, message, options);
  }
}

/**
 * 导演动作相关错误：不存在与状态冲突。
 *
 * `DIRECTOR_ACTION_STATE_CONFLICT` 的 `retryable` **必须由调用方指定**：
 * 「被并发抢先」值得重试一次（重新读状态再决定），
 * 「领域状态机不允许该转移」重试一万次也不会变，默认值猜不对。
 */
export class DirectorActionError extends SvhError {
  constructor(
    code: Extract<
      ErrorCode,
      'DIRECTOR_ACTION_NOT_FOUND' | 'DIRECTOR_ACTION_STATE_CONFLICT'
    >,
    message: string,
    options: SvhErrorOptions = {},
  ) {
    super(code, message, options);
  }
}
```

- [ ] **Step 9: 实现 `createClipBodySchema`**

`packages/domain/src/timeline.ts`：把 `createClipSchema` 整段替换为下面四块
（**字段表、判据函数、文案各只有一份**，两个面只是组装不同）。
镜头侧的 `createShotSchema` / `reorderShotsSchema` **不动** —— 它们没有 refine，
路由直接 `.omit({ contentId: true })` 即可（仓库既有写法）。

```ts
/** 片段的请求体字段（轨道由路径给出，故不含 trackId） */
const clipBodyShape = {
  shotId: idSchema.optional(),
  assetId: idSchema.optional(),
  startSeconds: clipStartSecondsSchema,
  durationSeconds: durationSecondsSchema,
};

/** 「恰好一个来源」的文案只写一遍：两个面共享同一条 refine 与同一句提示 */
const exactlyOneSourceIssue = { message: '片段必须且只能有一个来源（shotId 或 assetId）' };

/**
 * 创建片段（请求面）：轨道 + **恰好一个**来源 + 起点 + 时长。
 *
 * 为什么不复用 `createClipSchema.omit({ trackId: true })`：`.refine()` 之后是 `ZodEffects`，
 * 实测它**没有** `omit` 与 `extend`（zod 3.25.76）。所以在 domain 里同源派生两个面，
 * 而不是在路由上改造 schema —— 路由改不动，硬改就会退化成「收下再覆盖」的静默忽略。
 */
export const createClipBodySchema = z
  .object(clipBodyShape)
  .strict()
  .refine(hasExactlyOneSource, exactlyOneSourceIssue);

export type CreateClipBodyInput = z.input<typeof createClipBodySchema>;

/**
 * 创建片段（仓储面）= 请求面 + `trackId`。
 *
 * 形状与 V0.3-1 完全一致，仓储的写边界照旧 parse 它。
 */
export const createClipSchema = z
  .object({ ...clipBodyShape, trackId: idSchema })
  .strict()
  .refine(hasExactlyOneSource, exactlyOneSourceIssue);

export type CreateClipInput = z.input<typeof createClipSchema>;
```

```ts
/* ────────────────────────── V0.3-2 事件载荷 ────────────────────────── */

/**
 * 载荷的公共约束：**只带标识与状态，不带整行，也不带归属字段。**
 *
 * 归属（`sessionId` / `projectId`）由信封承担，两处各写一份必然漂移；
 * 整行则会让事件流变成快照堆积，`MAXLEN` 上限把有用的事件挤掉。
 */
const subjectIdSchema = idSchema.nullable();

/** 单行变更必须给得出主体；只有「一次影响多行」的批式动作允许 null */
function assertSubjectConsistent(
  value: { shotId?: string | null; clipId?: string | null; action: string },
  key: 'shotId' | 'clipId',
): boolean {
  const batchScoped = value.action === 'reordered' || value.action === 'tracks_ensured';
  return batchScoped ? value[key] === null : value[key] !== null;
}

export const shotChangedSchema = z
  .object({
    contentId: idSchema,
    shotId: subjectIdSchema,
    action: z.enum(['created', 'updated', 'deleted', 'reordered']),
  })
  .strict()
  .refine((value) => assertSubjectConsistent(value, 'shotId'), {
    message: 'reordered 之外的事件必须带 shotId；reordered 必须为 null',
    path: ['shotId'],
  });
export type ShotChangedEvent = z.infer<typeof shotChangedSchema>;

export const clipChangedSchema = z
  .object({
    contentId: idSchema,
    clipId: subjectIdSchema,
    action: z.enum(['created', 'updated', 'moved', 'deleted', 'tracks_ensured']),
  })
  .strict()
  .refine((value) => assertSubjectConsistent(value, 'clipId'), {
    message: 'tracks_ensured 之外的事件必须带 clipId；tracks_ensured 必须为 null',
    path: ['clipId'],
  });
export type ClipChangedEvent = z.infer<typeof clipChangedSchema>;

export const directorActionChangedSchema = z
  .object({
    actionId: idSchema,
    // 用领域枚举而不是自由字符串：14 种未接入的动作类型不该出现在事件里
    type: directorActionTypeSchema,
    status: directorActionStatusSchema,
    contentId: idSchema.nullable(),
  })
  .strict();
export type DirectorActionChangedEvent = z.infer<typeof directorActionChangedSchema>;
```

```ts
/**
 * Prisma 已知请求错误的识别工具
 *
 * 路由层不理解 Prisma（V0.3-2 spec §6 前置 6）：未知 id 必须是 404 + 域内错误码，
 * 而不是 `INTERNAL_ERROR` + 一条带 `Expected an existing record` 的 500。
 * 本文件是这条归一化的唯一零件，三个仓储都用它。
 *
 * 为什么按 `code` 判定而不是 `instanceof`：生成的客户端模块在包边界上可能有第二份类实例，
 * 那时 instanceof 静默为 false，坏错误就会一路漏到 500。字符串码是 Prisma 的稳定契约。
 */

/** 从任意值上安全取 `code` 字符串；取不到返回 null */
function readCode(err: unknown): string | null {
  if (typeof err !== 'object' || err === null) return null;
  const code = Reflect.get(err, 'code');
  return typeof code === 'string' ? code : null;
}

/** `P2025`：按条件更新 / 删除时记录不存在 */
export function isRecordNotFound(err: unknown): boolean {
  return readCode(err) === 'P2025';
}

/** `P2003`：外键约束不满足（例如往不存在的轨道上挂片段） */
export function isForeignKeyViolation(err: unknown): boolean {
  return readCode(err) === 'P2003';
}
```

```ts
export async function updateShot(id: string, patch: UpdateShotInput): Promise<StoryboardShotRow> {
  const parsed = updateShotSchema.parse(patch);

  // 读-合并-写三步必须在同一事务里：camera 是深合并的，
  // 并发的两个 patch 各改一个子键时，「先读后写」会让后写的那一个把先写的子键抹掉，
  // 而且毫无声音（V0.3-2 spec §6 前置 1）。
  return prisma.$transaction(async (tx: Prisma.TransactionClient) => {
    const current = await requireShot(tx, id);

    const data: Prisma.StoryboardShotUncheckedUpdateInput = {};
    if (parsed.durationSeconds !== undefined) data.durationSeconds = parsed.durationSeconds;
    if (parsed.description !== undefined) data.description = parsed.description;
    if (parsed.camera !== undefined) {
      // 深合并：与资产 metadata 的局部修改语义一致（null 表示显式清除）
      data.camera = deepMerge(
        (current.camera ?? {}) as Record<string, unknown>,
        parsed.camera,
      ) as Prisma.InputJsonValue;
    }
    if (parsed.emotion !== undefined) data.emotion = parsed.emotion;
    if (parsed.dialogue !== undefined) data.dialogue = parsed.dialogue as Prisma.InputJsonValue;
    if (parsed.imageAssetId !== undefined) data.imageAssetId = parsed.imageAssetId;
    if (parsed.videoAssetId !== undefined) data.videoAssetId = parsed.videoAssetId;
    if (parsed.status !== undefined) data.status = parsed.status;

    try {
      const updated = await tx.storyboardShot.update({ where: { id }, data });
      return toRow(updated);
    } catch (error) {
      // 事务内的先查后改仍可能被并发删除插队（READ COMMITTED 下不加行锁）：
      // 那一类失败也必须是 404，不能是 500。
      if (isRecordNotFound(error)) {
        throw new ShotError(`镜头 ${id} 不存在`, { context: { shotId: id }, cause: error });
      }
      throw error;
    }
  });
}
```

```ts
 * 删除镜头，并返回**被删掉的那一行**。

export async function deleteShot(id: string): Promise<StoryboardShotRow> {
  return prisma.$transaction(async (tx: Prisma.TransactionClient) => {
    const shot = await requireShot(tx, id);

    // asset_references 不是外键关联，数据库不会替我们清理，必须显式删
    await tx.assetReference.deleteMany({ where: { refType: SHOT_REF_TYPE, refId: id } });
    // 时间线片段由数据库级联删除（timeline_clips.shotId ON DELETE CASCADE）

    const rest = await tx.storyboardShot.findMany({
      where: { contentId: shot.contentId },
      orderBy: { index: 'asc' },
      select: { id: true },
    });
    await rewriteIndices(
      tx,
      shot.contentId,
      rest.map((row) => row.id),
    );

    return shot;
  });
}
```

```ts
 * 路由只在**要发事件**时才调它，所以不带 `sessionId` 的写请求不会多出这次读。
 */
export async function getTrackContentId(trackId: string): Promise<string> {
  const track = await prisma.timelineTrack.findUnique({
    where: { id: trackId },
    select: { contentId: true },
  });
  if (track === null) {
    throw new TimelineError('TIMELINE_TRACK_NOT_FOUND', `轨道 ${trackId} 不存在`, {
      context: { trackId },
    });
  }
  return track.contentId;
}

async function requireClip(
  tx: Prisma.TransactionClient,
  id: string,
): Promise<{ contentId: string; trackId: string; durationSeconds: number }> {
  const row = await tx.timelineClip.findUnique({
    where: { id },
    select: { track: { select: { contentId: true } }, trackId: true, durationSeconds: true },
  });
  if (row === null) {
    throw new TimelineError('TIMELINE_CLIP_NOT_FOUND', `片段 ${id} 不存在`, {
      context: { clipId: id },
    });
  }
  return {
    contentId: row.track.contentId,
    trackId: row.trackId,
    durationSeconds: row.durationSeconds,
  };
}

  trackContentId: string,
  shotId: string | null | undefined,
```

```ts
/**
 * 测试用的 SSE 读流助手
 *
 * ── 为什么不能用 app.inject ──
 * `inject()` 会把响应缓冲到结束才交回来，而 SSE 是永不结束的流：用它读事件
 * 会永远拿不到任何帧。所以这里用原始 fetch + reader。
 *
 * ── 为什么放在 helpers 而不是各测试文件内联 ──
 * 「怎么把一条流切成帧」是易错点（帧首可能是 `id:` 而不是 `event:`；开头的
 * `retry: 3000` 是独立一块；半包不是 JSON）。V0.3-2 有四个文件要读流，
 * 内联四份就会漂四次。文件名不带 `.test.ts`，vitest 不会把它当测试收集。
 */
import type { FastifyInstance } from 'fastify';

export interface StreamEnvelope {
  seq: number;
  type: string;
  at: string;
  sessionId?: string;
  projectId?: string;
  data: Record<string, unknown>;
}

export interface SessionStream {
  envelopes(): StreamEnvelope[];
  types(): string[];
  envelopesOfType(type: string): StreamEnvelope[];
  payloadOf(
    type: string,
    predicate: (data: Record<string, unknown>) => boolean,
  ): Record<string, unknown> | undefined;
  waitFor(predicate: () => boolean, timeoutMs?: number): Promise<void>;
  waitForReady(): Promise<void>;
  close(): void;
}

function baseUrlOf(app: FastifyInstance): string {
  const address = app.server.address();
  if (address === null || typeof address === 'string') throw new Error('未拿到监听端口');
  return `http://127.0.0.1:${String(address.port)}`;
}

export async function openSessionStream(
  app: FastifyInstance,
  sessionId: string,
  lastEventId?: string,
): Promise<SessionStream> {
  const frames: string[] = [];
  const controller = new AbortController();
  const response = await fetch(`${baseUrlOf(app)}/api/agent/sessions/${sessionId}/events`, {
    headers: lastEventId !== undefined ? { 'Last-Event-ID': lastEventId } : {},
    signal: controller.signal,
  });
  if (response.status !== 200) throw new Error(`SSE 建连失败：${String(response.status)}`);

  const reader = response.body?.getReader();
  void (async () => {
    if (reader === undefined) return;
    const decoder = new TextDecoder();
    try {
      for (;;) {
        const { done, value } = await reader.read();
        if (done) break;
        frames.push(decoder.decode(value, { stream: true }));
      }
    } catch {
      // 主动 abort 造成的读中断是预期行为
    }
  })();

  function envelopes(): StreamEnvelope[] {
    const out: StreamEnvelope[] = [];
    for (const block of frames.join('').split('\n\n')) {
      const lines = block.split('\n');
      const hasEvent = lines.some((line) => line.startsWith('event: '));
      const dataLine = lines.find((line) => line.startsWith('data: '));
      // 只认「同时有 event: 与 data: 行」的块：retry 行与半包都在这一步被筛掉
      if (!hasEvent || dataLine === undefined) continue;
      try {
        out.push(JSON.parse(dataLine.slice('data: '.length)) as StreamEnvelope);
      } catch {
        /* 半包，忽略 */
      }
    }
    return out;
  }

  async function waitFor(predicate: () => boolean, timeoutMs = 5000): Promise<void> {
    const started = Date.now();
    while (!predicate()) {
      if (Date.now() - started > timeoutMs) {
        throw new Error(`等待 SSE 事件超时，已收到：${JSON.stringify(envelopes().map((e) => e.type))}`);
      }
      await new Promise((resolve) => setTimeout(resolve, 50));
    }
  }

  return {
    envelopes,
    types: () => envelopes().map((envelope) => envelope.type),
    envelopesOfType: (type) => envelopes().filter((envelope) => envelope.type === type),
    payloadOf: (type, predicate) =>
      envelopes().find((envelope) => envelope.type === type && predicate(envelope.data))?.data,
    waitFor,
    waitForReady: () => waitFor(() => envelopes().some((envelope) => envelope.type === 'session.ready')),
    close: () => controller.abort(),
  };
}
```

```ts
import type { FastifyInstance } from 'fastify';

import { updateShotSchema, type UpdateShotInput } from '@svh/domain';
import { deleteShot, updateShot } from '@svh/database';

import { publishShotChanged } from '../core/change-events.js';
import {
  created,
  noContent,
  parseBody,
  parseDeliverySession,
  parseIdParam,
} from '../core/validate.js';

export async function shotRoutes(app: FastifyInstance): Promise<void> {
  /** 更新镜头。camera 是深合并（仓储侧实现），本层不碰 */
  app.patch('/:id', async (request) => {
    const id = parseIdParam(request);
    const patch = parseBody(request, updateShotSchema);
    const { sessionId } = parseDeliverySession(request);

    const updated = await updateShot(id, patch satisfies UpdateShotInput);
    await publishShotChanged(sessionId, {
      contentId: updated.contentId,
      shotId: updated.id,
      action: 'updated',
    });
    return updated;
  });

  /** 删除镜头：返回 204，删除的主体由事件载荷交代 */
  app.delete('/:id', async (request, reply) => {
    const id = parseIdParam(request);
    const { sessionId } = parseDeliverySession(request);

    // 载荷需要 contentId，而行删掉之后就再也读不到 —— 所以由 deleteShot **回传被删行**
    // （前置 10），这里不做「先 getShot 再 delete」的两次读。
    const deleted = await deleteShot(id);
    await publishShotChanged(sessionId, {
      contentId: deleted.contentId,
      shotId: deleted.id,
      action: 'deleted',
    });
    return noContent(reply);
  });
}
```

```ts
/**
 * 投递用的可选 `?sessionId=`。
 *
 * 它**不是业务字段**：镜头与片段挂在内容下，URL 给不出会话，
 * 所以「这条变化回声到哪条会话流」由客户端声明（与 `POST /api/tasks` 的
 * `sessionId` 同构）。为什么走 query 不走 body：更新类契约带 `.refine()`，
 * 是 ZodEffects，不接受 `.extend()` —— 为一个非业务字段重写契约是本末倒置。
 *
 * 不校验会话是否存在：既有做法如此（`publishSessionEvent` 对不存在的 id
 * 也只是往那条流写一笔，没人订阅就等于没发），本片不另立规矩。
 */
export const deliverySessionSchema = z.object({
  sessionId: z.string().min(1).max(64).optional(),
});

/** 读投递会话 */
export function parseDeliverySession(request: FastifyRequest): { sessionId: string | undefined } {
  return parseQuery(request, deliverySessionSchema);
}
```

```ts
/**
 * 时间线片段路由（按轨道 / 片段寻址的四条）
 *
 * 内容作用域的两条（GET 整棵树、补默认轨道）按仓库惯例写在 `contents.ts`。
 * 这里所有路由的 `contentId` 都不在 URL 上 —— 事件载荷却需要它，
 * 于是只在**要发事件**时经 `getTrackContentId` 反查一次：
 * 不带 `?sessionId=` 的请求不会因为发事件而多一次读。
 */
import type { FastifyInstance } from 'fastify';

import {
  createClipBodySchema,
  moveClipSchema,
  updateClipSchema,
  type CreateClipInput,
} from '@svh/domain';
import {
  createClip,
  deleteClip,
  getTrackContentId,
  moveClip,
  updateClip,
} from '@svh/database';

import { publishClipChanged } from '../core/change-events.js';
import {
  created,
  noContent,
  parseBody,
  parseDeliverySession,
  parseIdParam,
} from '../core/validate.js';

export async function timelineRoutes(app: FastifyInstance): Promise<void> {
  /** 在某条轨道上建片段。归属内容取自轨道，不接受客户端传 contentId */
  app.post('/tracks/:id/clips', async (request, reply) => {
    const trackId = parseIdParam(request);
    const body = parseBody(request, createClipBodySchema);
    const { sessionId } = parseDeliverySession(request);

    const clip = await createClip({ trackId, ...body } satisfies CreateClipInput);
    if (sessionId !== undefined) {
      await publishClipChanged(sessionId, {
        contentId: await getTrackContentId(clip.trackId),
        clipId: clip.id,
        action: 'created',
      });
    }
    return created(reply, clip);
  });

  /** 改片段的起点与时长（换轨走 move，两条路径的校验不同，不合并） */
  app.patch('/clips/:id', async (request) => {
    const id = parseIdParam(request);
    const patch = parseBody(request, updateClipSchema);
    const { sessionId } = parseDeliverySession(request);

    const updated = await updateClip(id, patch);
    if (sessionId !== undefined) {
      await publishClipChanged(sessionId, {
        contentId: await getTrackContentId(updated.trackId),
        clipId: updated.id,
        action: 'updated',
      });
    }
    return updated;
  });

  /** 移动片段：换轨与改起点的组合 */
  app.post('/clips/:id/move', async (request) => {
    const id = parseIdParam(request);
    const target = parseBody(request, moveClipSchema);
    const { sessionId } = parseDeliverySession(request);

    const moved = await moveClip(id, target);
    if (sessionId !== undefined) {
      await publishClipChanged(sessionId, {
        contentId: await getTrackContentId(moved.trackId),
        clipId: moved.id,
        action: 'moved',
      });
    }
    return moved;
  });

  /** 删除片段 */
  app.delete('/clips/:id', async (request, reply) => {
    const id = parseIdParam(request);
    const { sessionId } = parseDeliverySession(request);

    const deleted = await deleteClip(id);
    if (sessionId !== undefined) {
      await publishClipChanged(sessionId, {
        contentId: await getTrackContentId(deleted.trackId),
        clipId: deleted.id,
        action: 'deleted',
      });
    }
    return noContent(reply);
  });
}
```

```ts
import type { FastifyInstance } from 'fastify';
```

```ts
export async function directorRoutes(app: FastifyInstance): Promise<void> {
  /** 批准（重复批准幂等：返回既有行，不覆盖 confirmedAt） */
  app.post('/actions/:id/confirm', async (request) => {
    const id = parseIdParam(request);
    const action = await confirmAction(id);
    await publishDirectorActionChanged(action.sessionId, {
      actionId: action.id,
      type: action.type,
      status: action.status,
      contentId: action.contentId,
    });
    return action;
  });

  /** 拒绝一个待确认的提案（只有 awaiting_confirmation 可拒绝） */

    const id = parseIdParam(request);
    const { reason } = parseBody(request, reasonSchema);
    const action = await rejectAction(id, reason);
    await publishDirectorActionChanged(action.sessionId, {
      actionId: action.id,
      type: action.type,
      status: action.status,
      contentId: action.contentId,
    });
    return action;
  });

  /**
   * 取消。
   *
   * 与 reject 是**不同转移**（来源状态集不同：proposed / awaiting_confirmation /
   * approved / failed 都能取消，rejected 是终态），所以是独立路由而不是
   * 一条带 `?action=` 的开关。

    const id = parseIdParam(request);
    const { reason } = parseBody(request, reasonSchema);
    const action = await cancelAction(id, reason);
    await publishDirectorActionChanged(action.sessionId, {
      actionId: action.id,
      type: action.type,
      status: action.status,
      contentId: action.contentId,
    });
    return action;
  });
```

```ts
async function call<T>(
  method: 'GET' | 'POST' | 'PATCH' | 'DELETE',
  url: string,
  expectStatus: number,
  payload?: Record<string, unknown>,
): Promise<T> {
  const res = await app.inject({
    method,
    url,
    ...(payload === undefined ? {} : { payload }),
  });
  if (res.statusCode !== expectStatus) {
    throw new Error(
      `${method} ${url} 期望 ${String(expectStatus)}，实际 ${String(res.statusCode)}：${res.body}`,
    );
  }
  return (expectStatus === 204 ? (undefined as T) : (res.json() as T));
}
```
