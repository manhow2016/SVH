## 1. 背景与目标

V0.3 规范里，分镜、时间线、导演动作三块在当前仓库**全仓零命中**：没有 `storyboard_shots` /
`timeline_tracks` / `timeline_clips` / `director_actions` 表，没有 `StoryboardShot` / `Timeline*` /
`DirectorAction` 类型，没有测试。它们同时是 §61 Phase 7（Canvas + Storyboard + Timeline）与
§68 旗舰 Demo 的共同前置，因此作为 V0.3 的第一刀。

本片**只交付领域层与数据层**：类型、Zod 契约、一次迁移、仓储函数、以及 domain 与 database 两层的测试。
不含 API 路由、不含 UI、不含动作执行、不含渲染（分别属 V0.3-2 / V0.3-6 / V0.3-5 / 单独立项）。

目标可以一句话表述：**让「一个内容有 12 个有序镜头、三条轨道上有不重叠的片段、AI 的每项修改都有一条
可确认的结构化提案」这件事，在领域与数据两层成立且被测试锁住。**

## 3. 数据模型（新增 4 张表，既有表 0 列改动）

所有主键 `cuid()`，列名 camelCase（跟随仓库现状），表名 `@@map` 到下划线。

### 3.1 `storyboard_shots`

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | String @id @default(cuid()) | |
| `contentId` | String → `contents.id`，**Cascade** | 已决策：分镜挂 Content（规范 §8 的 Project 在本仓即 Content） |
| `episodeId` | String? | **分集预留列**：本轮不建 `episodes` 表、不加外键；§55 落地时只加外键，本表数据不动 |
| `index` | Int | 内容内从 0 连续；排序键 |
| `durationSeconds` | Float | 复用 `durationSecondsSchema`；与 EDL 同单位 |
| `description` | String @default("") | 画面描述 |
| `camera` | Json @default("{}") | `{shotType?, angle?, movement?}`，经 `cameraSchema` 校验 |
| `emotion` | String? | |
| `dialogue` | Json @default("[]") | `Dialogue[]`，经 `dialogueSchema` 校验 |
| `imageAssetId` | String? → `assets.id`，**SetNull** | 产物引用（资产是软删，外键恒有效） |
| `videoAssetId` | String? → `assets.id`，**SetNull** | 同上 |
| `status` | `ShotStatus` | `draft / generating / ready / failed` |
| `createdAt` / `updatedAt` | DateTime | |

约束：`@@unique([contentId, index])`、`@@index([contentId, status])`。

**镜头内的 `characters` / `scenes` / `props` 不建列也不建表**，写既有 `AssetReference`
（`refType = 'shot'`、`refId = shotId`）。理由：该表的语义正是「谁引用了这个资产」，
§37 的「18 个镜头引用了女主角」就是一次 `where { assetId, refType: 'shot' }`；
`@引用` 的资产影响面查询也复用同一条路径。
**代价**：读一个镜头的演员表要多一次查询（列表场景用一次 `IN` 批量取，避免 N+1）。

### 3.2 `timeline_tracks`

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | String @id @default(cuid()) | |
| `contentId` | String → `contents.id`，**Cascade** | 时间线属于内容 |
| `kind` | `TimelineTrackKind` | `video / audio / subtitle` |
| `label` | String @default("") | 如「BGM」「旁白」 |
| `order` | Int | 内容内自 0 连续 |

约束：`@@unique([contentId, order])`、`@@index([contentId, kind])`。

**`kind` 有意不唯一**：§28 的示意图里 Audio 轨之下还有 BGM 与 Voice 两条泳道，
所以同一内容允许多条 `audio` 轨，靠 `label` 区分。

### 3.3 `timeline_clips`

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | String @id @default(cuid()) | |
| `trackId` | String → `timeline_tracks.id`，**Cascade** | |
| `shotId` | String? → `storyboard_shots.id`，**Cascade** | 与 `assetId` **恰好一个非空** |
| `assetId` | String? → `assets.id`，**SetNull** | 同上 |
| `startSeconds` | Float | 轨内起点 |
| `durationSeconds` | Float | 片段时长 |
| `createdAt` / `updatedAt` | DateTime | |

约束：
- **恰好一个来源**：迁移 SQL 里手写
  `CHECK ((("shotId" IS NOT NULL)::int + ("assetId" IS NOT NULL)::int) = 1)`。
  Prisma schema 表达不了 CHECK —— 这是本仓第一次用，因此**必须配负向对照测试**
  （两列都给、两列都空都要被数据库拒绝）。
  domain 层用判别联合表达同一约束，两层护栏。
- `@@index([trackId, startSeconds])`。
- **同轨不重叠**由 domain 校验函数保证，不放进 DB（需要 `EXCLUDE USING gist` + 扩展，
  超出本轮收益）。
- 删镜头 → 其 clip 级联删除（clip 指向不存在的镜头只会渲染出空轨）；
  删资产**不**级联（资产走软删归档）；删轨道 → clip 级联。

### 3.4 `director_actions`

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | String @id @default(cuid()) | |
| `projectId` | String → `projects.id`，**Cascade** | 动作以项目为根 |
| `contentId` | String? → `contents.id`，**SetNull** | |
| `sessionId` | String? → `sessions.id`，**SetNull** | 复用会话：可追溯「哪轮对话提的」 |
| `actor` | `DirectorActor` | `user / agent` |
| `type` | `DirectorActionType` | §12 的 22 种全登记 |
| `targets` | Json @default("[]") | `[{ type, id }]` |
| `changes` | Json @default("{}") | 形状按 `type` 判别校验 |
| `status` | `DirectorActionStatus` | 见 §4.4 状态机 |
| `requiresConfirmation` | Boolean @default(false) | **由领域函数推导**，不接受调用方随意填 |
| `batchSize` | Int @default(1) | 必须等于 `targets.length` |
| `confirmedAt` / `executedAt` | DateTime? | |
| `result` | Json? | 执行层回写：`{ taskIds: string[] , summary?: string }` |
| `errorMessage` | String? | |
| `createdAt` / `updatedAt` | DateTime | |

约束：`@@index([projectId, status])`、`@@index([sessionId])`。

`type` 用 **Prisma 枚举**而非 String，这样 `enum-drift.test.ts` 会把 22 个取值与领域数组机械绑定：
任何一侧新增/删除取值，测试立即失败并指出差异。

### 3.5 对既有表的改动

只增加 Prisma 的**反向 relation 字段**（不产生任何列）：
`Content.shots` / `Content.tracks`、`Asset` 的三条（镜头产物两条 + clip 一条）、
`Project.directorActions`、`Session.directorActions`。

**可机械验收**：迁移 SQL 中不得出现对既有表的 `ALTER TABLE`（见 §8 验收标准第 3 条）。

## 4. 领域契约

新增三个文件（`packages/domain/src/`，并在 `index.ts` 导出）。

### 4.1 `storyboard.ts`

- `SHOT_STATUSES = ['draft','generating','ready','failed']`
- `cameraSchema`：`{ shotType?: string(≤32), angle?: string(≤32), movement?: string(≤32) }`，全可选、`.strict()`
  （**不**内置景别词表：规范 §25 只给字符串，词表属 UI 建议值，先不替产品定）
- `dialogueSchema`：`{ characterSlug?: slugSchema, text: string(1..500) }`
- `storyboardShotSchema`（读模型）、`createShotSchema`、`updateShotSchema`、`reorderShotsSchema`
  （`{ contentId, orderedShotIds: string[] }`）
- 纯函数：`assertContiguousIndices(shots)`、`reindex(orderedIds) → {id,index}[]`

### 4.2 `timeline.ts`

- `TIMELINE_TRACK_KINDS = ['video','audio','subtitle']`
- `timelineClipSourceSchema`：判别联合
  `{ source: 'shot', shotId }` | `{ source: 'asset', assetId }`
- `timelineSchema`（整棵树读模型：`tracks[]` 内含 `clips[]`）
- 纯函数：`assertNoOverlap(clipsInTrack)`（按 `startSeconds` 排序后相邻不重叠）、
  `timelineDurationSeconds(tracks)`（供 EDL 预览用）

### 4.3 `director.ts`

- `DIRECTOR_ACTION_TYPES`：§12 的 22 种全部登记
  （`create_project` `update_project` `create_story` `update_story` `create_script` `update_script`
  `create_asset` `update_asset` `delete_asset` `create_shot` `update_shot` `delete_shot`
  `reorder_shots` `generate_image` `generate_video` `generate_audio` `create_timeline`
  `update_timeline` `run_workflow` `run_task` `validate_project` `repair_project`）
- `DIRECTOR_ACTORS = ['user','agent']`
- **payload 注册表**：`DIRECTOR_ACTION_SCHEMAS`（按 type 索引）。本轮只注册**本片实体能校验**的 8 种：
  `create_shot` `update_shot` `delete_shot` `reorder_shots` `create_timeline` `update_timeline`
  `update_asset` `delete_asset`。
  未注册的 type 在**落库前被明确拒绝**（报「该动作类型尚未接入」），
  而不是留 TODO 占位、也不是静默忽略 —— 与仓库既有「未实现技能由任务终态明确表达」的口径一致。

  8 种已注册类型的 payload 形状（`targets` 统一为 `[{ type, id }]`，`batchSize = targets.length`）：

  | type | targets | changes |
  | --- | --- | --- |
  | `create_shot` | `[{type:'content', id}]` | `{ durationSeconds, description, camera?, emotion?, dialogue?, afterShotId? }` |
  | `update_shot` | `[{type:'shot', id}]`（批量可多个） | `{ durationSeconds?, description?, camera?, emotion?, dialogue? }` |
  | `delete_shot` | `[{type:'shot', id}]`（可多个） | `{}` |
  | `reorder_shots` | `[{type:'content', id}]` | `{ orderedShotIds: string[] }` |
  | `create_timeline` | `[{type:'content', id}]` | `{ tracks: [{ kind, label?, clips: [...] }] }` |
  | `update_timeline` | `[{type:'content', id}]` | `{ tracks?, clips? }` |
  | `update_asset` | `[{type:'asset', id}]`（批量可多个） | `{ changes: {...}, overwrite?: boolean }` |
  | `delete_asset` | `[{type:'asset', id}]`（可多个） | `{}` |

- `requiresConfirmation(action)` 纯函数，**只从 action 自身推导**（不新增数据库列）：

  ```text
  batchSize = targets.length
  overwrite = changes.overwrite === true          // 仅 update_asset 与 generate_* 的 schema 允许该键
  ALWAYS_CONFIRM_TYPES = { delete_asset, delete_shot, generate_image, generate_video,
                           generate_audio, run_workflow, run_task, repair_project }
  BATCH_CONFIRM_THRESHOLD = 1                     // batchSize > 1 即「批量修改 / 批量删除 / 批量生成」

  requiresConfirmation = ALWAYS_CONFIRM_TYPES.has(type)
                      || batchSize > BATCH_CONFIRM_THRESHOLD
                      || overwrite === true       // 覆盖现有版本
  ```

  「导出 / 发布」落在 task 级闸门（现有 `highCost` / `risk:'high'` 链路），不在本函数内重复表达。

### 4.4 状态机

```text
proposed              → awaiting_confirmation | approved | cancelled
awaiting_confirmation → approved | rejected | cancelled
approved              → executing | cancelled
executing             → executed | failed
failed                → approved | cancelled        （重试同一动作需重新批准）
executed / rejected / cancelled = 终态
```

表驱动实现（照 `domain/src/task-runtime.ts` 的 `TASK_TRANSITIONS` 写法），非法转移抛领域错误。

### 4.5 枚举登记

`domain/src/enums.ts` 增 5 组：`SHOT_STATUSES`、`TIMELINE_TRACK_KINDS`、`DIRECTOR_ACTORS`、
`DIRECTOR_ACTION_TYPES`、`DIRECTOR_ACTION_STATUSES`；`schema.prisma` 增同名 5 个枚举；
`enum-drift.test.ts` 的 `DOMAIN_ENUM_SOURCES` 补 5 行映射。

## 5. 不变量（每条一个测试）

1. `reorderShots` 只接受与现有镜头**集合完全相等**的 id 列表（不增不删）；执行后 `index` 为 `0..n-1` 连续。
2. 同内容内 `index` 唯一（DB 约束）且连续（domain 校验）。
3. clip **恰好一个来源**：domain 拒绝 + **DB 拒绝**（两层各一条测试）。
4. 同轨 clip 不重叠；跨轨允许重叠。
5. `batchSize` 必须等于 `targets.length`；批量动作的 `requiresConfirmation` 必为 `true`。
6. 动作状态机只允许 §4.4 白名单内的转移。
7. 删镜头级联删其 clip；删资产不级联（资产软删）。

## 6. 仓储与事务

### 6.1 `packages/database/src/storyboard.ts`

- `listShots(contentId)`：按 `index` 升序
- `createShot(input)`：追加到末尾（`index = max + 1`）
- `updateShot(id, patch)`：`camera` **深合并**（复用既有 `deepMerge`），`dialogue` 整体替换
- `deleteShot(id)`：同一事务内删行（clip 由 DB 级联）→ 删该镜头的 `AssetReference` 行
  （那不是外键，不会自动清理，见 §9 第 3 条）→ 把剩余 `index` 重排为连续
- `reorderShots(contentId, orderedShotIds)`：校验集合相等 → **两阶段重排**
- `syncShotAssetRefs(shotId, assetIds)`：对 `AssetReference` 做增删 diff，保持既有 unique 约束

**两阶段重排是必须的**：`@@unique([contentId, index])` 会让逐行 UPDATE 在中途撞唯一约束。
事务内先把该内容的 `index` 整体偏移到临时区间（如 `index + 100000`），再写入目标值。
必须有「把顺序完全打乱后重排仍成功」的测试 —— 否则只是碰巧没撞上。

### 6.2 `packages/database/src/timeline.ts`

- `getTimeline(contentId)`：一次查询取整棵树，clips 按 `startSeconds` 升序
- `ensureDefaultTracks(contentId)`：**幂等**，缺哪条补哪条，默认三条为
  「画面」(`video`) / 「声音」(`audio`) / 「字幕」(`subtitle`)，`order` 依次 0/1/2
- `createClip(input)` / `updateClip(id, patch)` / `moveClip(id, { trackId?, startSeconds? })` / `deleteClip(id)`
- 写入前调用 domain 的 `assertNoOverlap`（同事务内先读同轨 clips）

### 6.3 `packages/database/src/director-actions.ts`

- `createAction(input)`：校验 payload schema → 推导 `requiresConfirmation` → 初始状态
  `proposed`（无需确认时直接进 `approved`）
- `listActions(projectId, { status? })` / `getAction(id)`
- `confirmAction(id)` / `rejectAction(id, reason?)`：**幂等** —— 重复确认返回既有结果，不重复转移
- `markExecuting` / `markExecuted(id, result)` / `markFailed(id, error)`：**带 CAS**
  （状态必须仍是 `approved` / `executing`），照 `packages/database/src/tasks.ts` 的 Fencing 思路
- 与执行层的接口先留好：`result = { taskIds: string[] }`，V0.3-5 填；本片只保证字段存在且可写

## 9. 风险与注意事项

1. **`CHECK` 与 `db:push` 冲突**：`CHECK` 手写在迁移 SQL 里，而 `pnpm db:push` 会把数据库
   对齐到 Prisma schema，从而**丢掉该约束**。项目正常工作流是 `db:migrate`；这条限制写进
   `ARCHITECTURE.md` 的已知限制。
2. **单位统一为秒**（浮点，毫秒精度取整）：与 `durationSecondsSchema`、EDL 一致。
   若将来引入毫秒整数，必须一次改全链路，不做两套单位共存。
3. **`AssetReference` 复用不是外键**：「镜头 → 资产」的引用行没有 `storyboard_shots` 外键，
   删镜头时引用行不会自动清理，需在 `deleteShot` 里显式删（测试覆盖）。
4. **软删语义**：`DELETE /api/contents/:id` 只写 `archivedAt`，级联不会触发 ——
   归档内容的分镜与时间线仍在库里（可恢复），这是有意的。
5. **规范内部不一致**：§11 的示例用了 `update_character`，该值不在 §12 的 22 种清单里。
   **按 §12 为准**，该示例用 `update_asset` 表达。
6. **14 种未注册的动作类型**必须在仓储层被明确拒绝并给出可读文案，
   不允许「静默落库但没人执行」。
